## v2.5.5.2 — Brave 1.93.136 Validation & ADMX CI Fixes

**Patch release — Brave version bump, critical Reset-mode regression fix, and ADMX validator auto-discovery. No policy changes.**

### Summary

v2.5.5.2 validates full compatibility with Brave **1.93.136** (Chromium **151.0.7922.137**; 1.93.129 / 151.0.7922.71 remains supported) and fixes a critical Reset-mode regression where `$HKCU_Target`/`$HKLM_Target` path constants were defined after the Reset block, causing `Test-Path $null` crashes under PowerShell 5.1. The ADMX validator no longer hardcodes a partial policy map — it auto-discovers all 150 policies and supports documented exceptions for Chromium policies intentionally absent from Brave's ADMX.

| Metric | Before (v2.5.5.1) | After (v2.5.5.2) |
|--------|-------------------|-------------------|
| Hardening levels | 5 | 5 |
| Total policies | 150 | 150 |
| Cumulative chain | 24→52→84→122→150 | 24→52→84→122→150 |
| Script version | v2.5.5.1 | v2.5.5.2 |
| Validated Brave | 1.93.129 | 1.93.136 |

### Changed

- Script version → `v2.5.5.2` (EN + TR) — no policy definitions changed
- **Brave version bump** — validated against Brave **1.93.136** (Chromium 151.0.7922.137); 1.93.129 (Chromium 151.0.7922.71) remains supported
- **Reset-mode fix** — `$HKCU_Target`/`$HKLM_Target` path constants moved above the Reset block (EN + TR); previously defined after, causing `Test-Path $null` crashes in PowerShell 5.1
- `admx/admx-validate.ps1` — auto-discovers all 150 policies from `BraveOmega-EN.ps1`; added documented-exception mechanism for Chromium policies intentionally absent from Brave's ADMX (e.g. `DeviceAttributesAllowedForOrigins`)
- Tests — regression tests added for Reset-mode path-constant ordering (`ResetMode.Tests.ps1`) and full ADMX coverage + documented exceptions (`ADMXCrossReference.Tests.ps1`)
