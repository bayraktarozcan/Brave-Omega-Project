## v2.5.4.0 — Deterministic Registry State & Download Control Relaxation

**Self-healing release — stale policy cleanup on every run, plus download control relaxed below Strict so legitimate downloads are never blocked.**

### Summary

Brave Omega now performs a **stale policy cleanup** before writing: any Omega-managed value under `HKLM\SOFTWARE\Policies\BraveSoftware\Brave` that is not part of the selected tier's merged policy set is automatically removed on every run. Foreign/non-Omega values are always preserved.

Download control relaxed **below Strict**: `SafeBrowsingDeepScanningEnabled` moved from Essential to Strict, `DisableSafeBrowsingProceedAnyway` moved from Balanced to Strict, and `DownloadRestrictions` removed from Balanced (Strict already enforces the full block via Value=3). Balanced and Advanced keep the Safe Browsing warning but let the user proceed — legitimate downloads (e.g. driver installers) are never stopped by the "blocked by your organization" message. Strict retains full deep-scanning, no-proceed enforcement, and the complete download block (3).

| Metric | Before (v2.5.3.0) | After (v2.5.4.0) |
|--------|-------------------|-------------------|
| Hardening levels | 5 | 5 |
| Total policies | 150 | 150 |
| Cumulative chain | 24→52→85→123→150 | **24→51→82→120→150** |
| Stale cleanup | Only with `-Reset` / tier downgrades | **On every run** |
| Foreign values | — | Preserved |

### Added

- **Stale policy cleanup** — On every run, Omega-managed HKLM values no longer in the selected tier's merged set are removed automatically (WhatIf-aware, per-value try/catch, success/failure counters). `-Reset` shares the same deterministic policy name source (`$allPolicyNames`)
- **Summary report line** — `Stale Cleanup : <n> removed / <n> failed`
- **Exit-code integration** — a failed stale cleanup now results in exit code 1
